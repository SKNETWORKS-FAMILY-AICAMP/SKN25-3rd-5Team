# 🧪 테스트 계획 (Test Plan)

## 1. 개요
본 프로젝트는 **Streamlit 기반 프론트엔드 + FastAPI 백엔드 + 벡터 검색 및 LLM(RAG)** 구조로 구성되어 있으며,  
시스템의 안정성과 응답 품질을 검증하기 위해 테스트를 수행한다.

테스트는 다음 4개 영역으로 구분한다.

- 백엔드 API 및 서비스 통합
- 핵심 비즈니스 로직
- 데이터 품질
- UI 및 사용자 흐름

---

## 2. 테스트 범위

### 2.1 백엔드 API 테스트
다음 주요 API의 정상 동작을 검증한다.

- `/recommend` : 여행지 추천
- `/chat` : 챗봇 응답
- `/plan` : 일정 생성
- `/data-status` : 데이터 상태 확인

검증 항목:
- 정상 요청 시 올바른 JSON 응답 반환
- 입력 validation 동작 여부
- 오류 발생 시 예외 처리

---

### 2.2 핵심 비즈니스 로직 테스트

#### 📌 Retriever 로직
- `retrieve_category`, `retrieve_plan` 결과 변환 검증
- `extract_selected_place` 히스토리 기반 장소 추출 확인
- `build_chat_query` 후속 질문 확장 로직 검증
- `is_meta_chat` 메타 질문 판별 정확도 확인

#### 📌 LLM 처리 로직
- `parse_category_json` JSON 파싱 및 예외 처리
- `generate_*` 함수의 프롬프트 생성 검증
- 실제 API 호출 대신 mock을 활용한 테스트 수행

---

### 2.3 통합 테스트

여러 컴포넌트가 함께 동작하는지 검증한다.

- 추천 흐름: API → Retriever → LLM → 응답
- 일정 생성: DB 조회 → LLM 일정 생성
- 챗봇: 대화 히스토리 기반 응답 생성

---

### 2.4 데이터 품질 테스트

데이터셋 및 DB 상태를 검증한다.

- 필수 컬럼 존재 여부
- null 값 허용 범위 확인
- `/data-status` API 정상 동작 확인

---

### 2.5 UI 및 사용자 흐름 테스트

Streamlit 기반 UI는 다음 항목을 중심으로 검증한다.

- 페이지 정상 렌더링
- 여행 추천 기능 동작
- 챗봇 대화 흐름 유지
- 일정 생성 결과 출력

※ UI는 자동화보다는 **수동 및 스모크 테스트 중심**으로 수행한다.

---

## 3. 테스트 종류

### ✔️ 단위 테스트
- 함수 단위 입력/출력 검증
- retriever, llm 로직 중심

### ✔️ 통합 테스트
- API + DB + LLM 전체 흐름 검증

### ✔️ 데이터 테스트
- 데이터 무결성 및 상태 검증

### ✔️ 스모크 테스트
- 서비스 실행 여부 및 기본 기능 확인

---

## 4. RAG 성능 테스트

- Precision@3, Recall@3 기반 평가
- 사용자 질문 대비 관련 데이터 포함 여부 확인
- hallucination 발생 여부 정성 평가

---

## 5. 예외 및 실패 테스트

- LLM 응답이 JSON 형식이 아닐 경우 처리
- DB 연결 실패 시 fallback 처리
- 검색 결과가 없는 경우 기본 응답 제공

---

## 6. 테스트 도구

- pytest
- FastAPI TestClient
- unittest.mock / pytest-mock
- pandas

## 7. 결론

본 테스트 계획은  
백엔드 로직, API 흐름, 데이터 품질, RAG 기반 응답의 신뢰성을 중심으로 설계되었으며,  
특히 LLM의 불확실성을 고려한 예외 처리 및 retrieval 기반 검증을 포함한다.
